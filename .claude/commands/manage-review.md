A new review has come in on the current PR. Analyze it critically.

Do not apply the review blindly, and do not defend the code. Read the relevant code to check each point before judging it. Do not modify any files.

## Workflow

1. Break the review into individual points.
2. For each point, decide: Valid (worth fixing), Partially valid (real concern, better fix exists), or Not worth it (wrong, out of scope, or cost outweighs benefit). Give a one or two sentence reason based on what you verified in the code.
3. Write an implementation plan covering only the Valid and Partially valid points: ordered steps, the files involved, and how to verify each one.
4. List anything you're rejecting, with a short reason I can pass back to the reviewer.

5. Then stop and wait for my approval before implementing anything.
